# Implementation boundaries and submission notes

This version repairs the ungated IER path and accepted-task five-rule SVR logs.
Related experiments, comparisons, demo traces and presentation results were
regenerated. Static input data, safety predicates, narrator templates, baseline
ranking methods and hyperparameters were not changed by this repair.

## Measurement

- Pipeline IER measures an ungated all-candidate top-5 ranking against the
  current feasible set, including the emotional difficulty cap. SAPS calls
  `select_raw_topk`; its normal recommendation output retains its safe-arm gate.
  This replaces the prior gated measurement rather than adding another sampling
  pass. The resulting infeasible IDs also drive existing negative reward updates,
  so SAPS learning and reward change. No RNG or hyperparameter was added.
- Every pipeline log emits `safety_violation`. Only accepted tasks are audited
  against all five pre-filter predicates through a separate enabled SafetyAgent
  using configured thresholds, independent of runtime enable/drop_rule settings.
  Rejected offers and blocked candidates are not execution violations. Dosage
  limits and emotional caps are outside this five-predicate SVR definition.
- `evaluation/metrics.py` uses the explicit observation or replays legacy logs
  through the same five-rule implementation, including ROM. Legacy replay uses
  default thresholds because those old logs lack configured-threshold metadata.
- Formal per-user summaries divide by accepted counts, then retain macro
  averaging. NoSafety macro SVR is 0.2181; pooled post-hoc 171/772 is 0.2215.
  Both are valid aggregations and must not be presented as identical quantities.
- Formal runner diversity is unique chosen task IDs divided by interactions
  per persona. It is not Diversity@10 or the separate category diversity helper.
- One learning model is shared across users. Simulator randomness is consumed
  sequentially, and NeuralUCB warm-start consumes additional state draws.
  Per-person paired tests summarize the fixed simulated cohort; independence
  and identical realized user-day noise across policies are not guaranteed.

## Models and safety

SAPS samples Beta safety only, not reward parameters. Its Beta state is indexed
by task, shared across users and updated from chosen-task pain_change <= 1.0.
The reward side is disjoint LinUCB. The penalty coefficient is configured and
scaled by narrative act; it is not a learned Lagrange multiplier.

The modified NeuralUCB adds the same network prediction to each arm's score,
so that term cancels in ranking. Its arm means and Gaussian noise determine
ranking. RuleBased assigns all arms the same score; supplied order breaks ties.
Popularity ranks by mean reward. These are limited references, not evidence
that SAPS outperforms original gradient-UCB or a strong clinical rule ranker.

The five runtime pre-filters are implemented in `src/agents/safety_agent.py`.
The 51 JSON definitions exist but are not all executable runtime checks.
CR/DR/FR lists are not interpreted by pre_filter; post_check looks for
`dosage_limits`, which is absent and thus uses defaults. Crisis definitions
are used by the interactive crisis path; progression gates have an API but
are not invoked by the main simulation. No universal clinical guarantee follows.

## Cold-start and simulation limits

The cold-start `freeze_updates` disables recommender reward updates only.
Pipeline calls to `model.update_safety` still adapt SAPS Beta parameters.
The current reward-frozen minus retrained difference is -1.3420 (raw p=0.0350)
on five BP users. Their reward means are 42.01 and 43.35, with IER 0.0080 and
0.0627. This is a fixed small-cohort trade-off, not evidence of robust transfer.

Profile conditions use long names, but narrative arc keys are ACL/RotatorCuff/
BackPain. Narrator currently falls back to ACL for these profiles. The pipeline
starts at index zero, outside arc day ranges, so its first act resolves to act3.
The default progression is act3 -> act1 -> act2 -> act3. HTML labels its own
Forest/Canyon/Summit presentation and discloses this difference.

Feedback simulation can increment internal completed-task counters before the
pipeline changes a rejected action's completed flag to false. Consequently,
simulated ROM progression must not be interpreted as a validated clinical
response restricted to accepted exercises. Pain/fatigue and ROM evolution are
stylized, not real-patient longitudinal evidence.

## Reproduction coverage

`reproduce_all.sh` regenerates core policy, safety and narrative-sample outputs.
It compares pre-existing Random and cold-start artifacts without regenerating
them. Cold-start is separately regenerated by `reproduce_coldstart.sh`.
Paired tests and external judge scores are separate workflows. Paired tests,
Random, LinUCB's separate summary and cold-start were regenerated for this
version. External judge scores remain attached to unchanged LinUCB narrative
samples. A repeated core run passed 13/13 comparisons against regenerated references.
Exact comparison can still report cross-machine last-ULP drift; only
wall_time_s is stripped. Verification failure messages do not currently force
a nonzero script exit code.

The artifact `narrator_invariants_60day_seed42.json` is an initial diagnostic,
not the final I3 conclusion: it records 88 false negatives while its pass
condition only excludes false positives. The corrected interpretation is in
`narrator_invariants_v2_60day_seed42.json`. Both remain because the active
reproduction scripts produce them. Closing follow-up matches the pipeline's
logged IER-derived safety flag, not every pre-filter candidate removal.

## Current empirical interpretation

After the repair, SAPS reward is 42.0182 versus LinUCB 41.9395. The paired
fixed-cohort reward p-value is 0.7429 and IER p-value is 0.6295. The old +4.35
reward advantage and zero raw IER do not describe this implementation. Random
remains higher on reward. No independent Beta-only causal benefit is claimed:
the repair activates the existing infeasible-arm penalties too. See the current
policy and paired-test JSON files for full precision.
