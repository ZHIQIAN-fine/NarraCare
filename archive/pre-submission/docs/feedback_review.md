# Local feedback correction review

## Status and scope

Unpublished working changes based on main `660e85a`. No GitHub push or release is part of this review. Historical experiment artifacts, numerical input JSON, policy parameters and reward weights are preserved. The old report/deck/HTML describe the historical protocol until separately updated.

## Correctness changes

- A rejected task never calls `simulate_feedback`. It produces no pain/fatigue/ROM/satisfaction result, no completion counter increment, and no chosen-arm reward or Beta update. Behavioral skip memory remains. Zero reward is aggregate bookkeeping with `reward_observed=false`, not an observed physical outcome.
- Actually attempted tasks, including partial attempts, retain the existing feedback and reward calculation. Known infeasible raw proposals retain the existing constraint-penalty updates; these use known predicates, not invented physical outcomes.
- The previous unfiltered rest/catalogue fallback is removed. A post-check recovery fallback passes checks, and every final shortlist is pre-filtered again. An impossible catalogue raises a visible coverage error instead of injecting unsafe tasks or silently dropping days.
- Guided check-in/preferences and outcome forms prepare explicit English messages. Users review and Send them through the same LLM tool controller. No defaults are invented for symptoms. ROM can remain unknown.
- An explicit report that pain prevents any task, with no task performed, can pause a day without reward or learning. A numeric pain score alone is not a new stopping threshold. Existing red-flag holds remain in force. Users can still decline an assigned task.
- Satisfaction is stored descriptively in session outcome records but remains absent from the reward formula. No medical-record import or persistence service was added.
- Live-provider testing exposed omitted preference updates and incomplete outcome evidence. Retrieval now requires stated preferences to be processed, and the feedback tool schema constrains evidence to the complete current user message. Original numeric, range, evidence and sequencing guards remain active.

## What the safety checks establish

Coverage tests use the 20 existing synthetic profiles and four states: (pain,fatigue,ROM,mood) = (2,2,110,7), (7,8,59,3), (9,9,0,2), (3,8,60,5). Repeating them with bonus weights 0, 2 and 100 gives 240 boundary checks with feasible tasks. This is a constraint-invariance stress test, not a performance grid search or clinical certification. A deliberately infeasible test catalogue raises a coverage error. No invented recovery task bypasses constraints.

Safety bonus changes ranking. Runtime predicates/post-checks constrain delivery. IER is ungated top-5 infeasibility against the feasible set (including emotional caps); SVR is accepted-task violation of five implemented predicates. These are not medical harm probabilities. Beta uses the separate pain-change <= 1 proxy.

## Minimal bonus ablation: ten independent seed runs

Fixed before comparison: seeds 42–51, tau_safe = 0 versus 2, alpha_ucb = 1, same priors/filter/penalty/reward weights and corrected feedback path. Both settings retain model RNG sampling, so disabling the term does not simply remove RNG draws. This is a bonus-term ablation, not LinUCB equivalence, a parameter search, or a held-out validation procedure. Same seeds do not imply identical realized simulator noise once action histories diverge. Each seed is one paired experimental unit; personas sharing a learner are not treated as independent repeats.

Across all 20 runs, every run has 1200 assigned tasks and SVR=0; skips have no pain outcome and completion counters match completed feedback. The IER difference is about -0.068 percentage points. Its raw p is below .05 but it does not pass the three-comparison Bonferroni adjustment; results are exploratory. No stable reward or acceptance benefit is established. Negative Beta observations remain very scarce (0–3 per on-run), limiting discrimination of the sampled safety term.

## Follow-up recommendation

1. Defer a tau grid and broad performance search: the extra term has no established reward gain here, and searching the same seeds risks selection bias. Establish an independent development/test protocol before tuning.
2. A separate top-1/top-3 and shortlist-composition diagnostic is a more targeted next investigation of Random's higher corrected reward. It has not been performed in this review. The simulator chooses its highest-utility item among the supplied shortlist; this is a mechanism to investigate, not a proven explanation.
3. Do not change evaluation reward weights to make SAPS win. Do not relabel simulated constraints or pain proxies as validated clinical safety.

Legacy reproduce scripts target historical result filenames and must not be run in this checkout to overwrite the preserved references. Old cold-start, narrative-judge and HTML artifacts have not been regenerated and must not be presented as corrected-path results.

## Remaining boundaries

The catalogue remains authored synthetic data with no per-record clinical provenance or sign-off. The 240 checks verify implemented behavior only. LLM behavior is not universally reliable; successful smoke/browser sequences do not establish long-session robustness, clinical safety or engagement gains. Existing benchmark narrator condition/day mappings and modified baseline limitations are unchanged. There is no new validation set, real-patient study, EHR integration, or top-1/top-3 performance experiment.
